# KCC Mission Control - Project Handover Document

## Project Overview
This project is a custom wireless telemetry system built for "KCC Mission Control." It reads environmental and IMU sensor data on a transmitter node (Teensy 4.1) and blasts it over LoRa (440 MHz) to a receiver node (ESP32). The ESP32 acts as a standalone Wi-Fi Access Point and Web Server, directly hosting a highly-styled retro HTML dashboard that live-streams the incoming telemetry.

## Hardware Configuration
### 1. Transmitter Node (Teensy 4.1)
- **LoRa Module (SX1278):** SPI interface. CS=10, RST=9, DIO0=2.
- **IMU (MPU6050/9250):** I2C interface (Address `0x68`). Reads Z-Axis G-force.
- **DHT11:** Connected to Digital Pin 3.
- **LDR (Light Sensor):** Connected to Analog Pin A0 (Pin 14). Configured for 12-bit ADC resolution (0-4095).
- **Behavior:** The Teensy reads the sensors continuously (DHT11 is paced to every 2 seconds to avoid blocking). It constructs a string payload (`Data -> Temp:XX.X Hum:XX.X LDR:XXXX AccelZ:X.XX`) and transmits it via the LoRa radio every 50ms using async `LoRa.endPacket(true)`.

### 2. Receiver Node (ESP32)
- **LoRa Module (SX1278):** SPI interface. CS=5, RST=14, DIO0=2.
- **Behavior:**
  - Configures itself as a SoftAP (SSID: `ESP32_LoRa_Plotter`, Password: see the sketch).
  - Runs a web server on `http://192.168.4.1`.
  - The root endpoint `/` serves the embedded HTML/CSS/JS dashboard.
  - The `/data` endpoint returns the latest received telemetry as a JSON object.
  - Continuously parses incoming LoRa packets, extracts the values using string manipulation, and updates the internal state.

## Software Architecture
- The original laptop-based Python/Flask app (`app.py`) was **abandoned**. The entire UI has been ported to an embedded C++ string (`html_page`) inside the ESP32 firmware.
- The web UI uses standard `fetch()` polling every 100ms to pull the JSON data from the ESP32.
- The UI features CSS-animated analog meter needles (mapped to AccelZ) and a `Chart.js` scrolling graph (mapped to the LDR).
- **Chart.js Fallback:** Since the ESP32 network has no internet, devices connected to it cannot reach the Chart.js CDN. A `try-catch` block was implemented to prevent the entire dashboard from crashing if the CDN fails to load.

## Current Status & Known Quirks
1. **Fully Functional:** The data successfully transmits, the ESP32 successfully receives it, and the embedded website successfully streams it.
2. **Teensy Overlapping Transmissions:** The Teensy loop runs every 50ms, but a 60-byte payload at SF7 takes ~100ms to transmit over LoRa. Because `LoRa.endPacket(true)` is non-blocking, the Teensy stuffs multiple overlapping payloads into the radio FIFO buffer. The ESP32 receives massive packets containing duplicated strings (e.g., `Data -> Temp... Data -> Temp...`). The ESP32 parser (`extractValue`) handles this gracefully by just grabbing the first occurrence, so it doesn't break the system, but the Teensy pacing could be optimized later.
3. **User Confusion:** The user was running their old local Python Flask app (`localhost:5000`) and wondering why the data wasn't updating, without realizing the live website is now hosted exclusively on the ESP32 at `192.168.4.1`.

### 1. Transmitter Node (Teensy 4.1)

#include <SPI.h>
#include <LoRa.h>
#include <Wire.h>
#include <DHT.h>

// Pins
#define LORA_CS    10  
#define LORA_RST   9   
#define LORA_DIO0  2   
#define LDRPIN     A0  
#define DHTPIN     3   
#define DHTTYPE    DHT11 

DHT dht(DHTPIN, DHTTYPE);

bool mpu_found = false;
uint8_t mpu_addr = 0x68;

float lastTemp = 0.0;
float lastHum = 0.0;
unsigned long lastDHTRead = 0;

void setup() {
  Serial.begin(115200);
  delay(1000);
  Serial.println("KCC Full Sensor Node Starting...");

  pinMode(LDRPIN, INPUT);
  analogReadResolution(12);
  dht.begin();
  Wire.begin();
  
  // RAW I2C IMU INITIALIZATION (Bypasses Who-Am-I checks)
  Wire.beginTransmission(0x68);
  if (Wire.endTransmission() == 0) {
    mpu_found = true;
    mpu_addr = 0x68;
    Serial.println("IMU found at 0x68!");
  } else {
    Wire.beginTransmission(0x69);
    if (Wire.endTransmission() == 0) {
      mpu_found = true;
      mpu_addr = 0x69;
      Serial.println("IMU found at 0x69!");
    } else {
      Serial.println("IMU not found! (Will skip reading it)");
    }
  }

  if (mpu_found) {
    // Wake up the IMU
    Wire.beginTransmission(mpu_addr);
    Wire.write(0x6B); // PWR_MGMT_1
    Wire.write(0x00); // Wake up
    Wire.endTransmission();
  }

  // Reset LoRa
  pinMode(LORA_RST, OUTPUT);
  digitalWrite(LORA_RST, LOW);
  delay(100);  
  digitalWrite(LORA_RST, HIGH);
  delay(100);  

  SPI.begin();
  LoRa.setSPI(SPI);
  LoRa.setSPIFrequency(1000000); 
  LoRa.setPins(LORA_CS, LORA_RST, LORA_DIO0);
  
  while (!LoRa.begin(440E6)) { 
    Serial.println("Starting LoRa failed! Check wiring!");
    delay(1000);
  }
  
  LoRa.setTxPower(20);
  LoRa.setSpreadingFactor(7);
  LoRa.setSignalBandwidth(125E3);
  LoRa.enableCrc();
  Serial.println("LoRa is ready at 440MHz! SPAMMING ALL SENSORS!");
}

void loop() {
  if (millis() - lastDHTRead >= 2000) {
    float t = dht.readTemperature();
    float h = dht.readHumidity();
    if (!isnan(t)) lastTemp = t;
    if (!isnan(h)) lastHum = h;
    lastDHTRead = millis();
  }

  int ldr = analogRead(LDRPIN);
  
  String payload = "Data -> Temp:" + String(lastTemp) + " Hum:" + String(lastHum) + " LDR:" + String(ldr) + " ";

  if (mpu_found) {
    // RAW I2C ACCEL Z READ
    Wire.beginTransmission(mpu_addr);
    Wire.write(0x3F); // ACCEL_ZOUT_H
    Wire.endTransmission(false);
    Wire.requestFrom((uint8_t)mpu_addr, (uint8_t)2, (uint8_t)true);
    if (Wire.available() == 2) {
      int16_t az_raw = Wire.read() << 8 | Wire.read();
      float accel_z_g = az_raw / 16384.0; // Default sensitivity is +/- 2g
      payload += "AccelZ:" + String(accel_z_g) + " ";
    }
  }

  // Debug Print so I can see it!
  Serial.println(payload);

  LoRa.beginPacket();
  LoRa.print(payload);
  LoRa.endPacket(true); 

  delay(50); 
}

void handleRoot() {
  server.send(200, "text/html", html_page);
}

void handleData() {
  String json = "{";
  json += "\"ldr\":" + String(current_ldr) + ", ";
  json += "\"accelz\":" + String(current_accelz) + ", ";
  json += "\"temp\":" + String(current_temp) + ", ";
  json += "\"hum\":" + String(current_hum) + ", ";
  json += "\"rssi\":" + String(current_rssi) + ", ";
  json += "\"pkts\":" + String(packetCount) + ", ";
  json += "\"raw\":\"" + latest_payload + "\"";
  json += "}";
  Serial.println(json);
  server.send(200, "application/json", json);
}

void setup() {
  Serial.begin(115200);

  WiFi.softAP("ESP32_LoRa_Plotter", "<redacted>");

  server.on("/", handleRoot);
  server.on("/data", handleData);
  server.begin();

  pinMode(LORA_RST, OUTPUT);
  digitalWrite(LORA_RST, LOW);
  delay(100);  
  digitalWrite(LORA_RST, HIGH);
  delay(100);  

  LoRa.setPins(LORA_CS, LORA_RST, LORA_DIO0);
  
  while (!LoRa.begin(440E6)) {
    delay(1000);
  }
  
  LoRa.setSpreadingFactor(7);
  LoRa.setSignalBandwidth(125E3);
  LoRa.enableCrc();
}

String extractValue(String payload, String key) {
  int index = payload.indexOf(key);
  if (index == -1) return "";
  int spaceIndex = payload.indexOf(" ", index);
  if (spaceIndex == -1) spaceIndex = payload.length();
  return payload.substring(index + key.length(), spaceIndex);
}

void loop() {
  server.handleClient();

  int packetSize = LoRa.parsePacket();
  if (packetSize) {
    packetCount++;
    String receivedText = "";
    while (LoRa.available()) {
      receivedText += (char)LoRa.read();
    }
    
    current_rssi = LoRa.packetRssi();
    latest_payload = receivedText;
    // Strip quotes/newlines from payload to avoid breaking JSON
    latest_payload.replace("\"", "'");
    latest_payload.replace("\n", "");
    latest_payload.replace("\r", "");

    String val = extractValue(receivedText, "LDR:");
    if (val != "") current_ldr = val.toInt();

    val = extractValue(receivedText, "AccelZ:");
    if (val != "") current_accelz = val.toFloat();
    
    val = extractValue(receivedText, "Temp:");
    if (val != "" && val != "ERR") current_temp = val.toFloat();
    
    val = extractValue(receivedText, "Hum:");
    if (val != "" && val != "ERR") current_hum = val.toFloat();
    
    String json = "{";
    json += "\"ldr\":" + String(current_ldr) + ", ";
    json += "\"accelz\":" + String(current_accelz) + ", ";
    json += "\"temp\":" + String(current_temp) + ", ";
    json += "\"hum\":" + String(current_hum) + ", ";
    json += "\"rssi\":" + String(current_rssi) + ", ";
    json += "\"pkts\":" + String(packetCount) + ", ";
    json += "\"raw\":\"" + latest_payload + "\"";
    json += "}";
    
    Serial.print("JSON: ");
    Serial.println(json);
  }
}

### Update 26 Sep 2026 (later): unattended / battery operation
Both boards now recover without a laptop attached. Both watchdogs were tested on the bench with a
deliberate hang, and each board rebooted itself (Teensy after ~8 s, ESP32 after ~20 s).
- **Teensy:** software watchdog (IntervalTimer ISR → `SCB_AIRCR` reset if `loop()` stalls 8 s).
  The radio is re-initialised if `beginPacket()` refuses packets for 2 s, or if register 0x06
  (FRF MSB) no longer reads 0x6E (= 440 MHz). An SX1278 brownout resets it to 434 MHz defaults.
  If LoRa init fails 15 times at boot, the Teensy reboots.
- **ESP32:** task watchdog stretched to 20 s and applied to `loop()`. Wi-Fi is re-joined every 30 s
  while down, and the board reboots if the broker is unreachable for 10 min with Wi-Fi up. The radio
  is re-initialised after 60 s without packets or on an FRF mismatch. `setSocketTimeout(8)`: the
  first MQTT connect after boot timed out at 3 s on CU_EVENT.
- Opening `/dev/ttyUSB0` from the laptop resets the ESP32 (USB-serial adapter toggles EN). This is
  harmless and doesn't happen on battery.

## Update 5 Oct 2026 (night): 1U yaw

At the user's request the 1U node firmware gained gyro yaw (the only change; Teensy USB serial 17994270):
- At power-up it measures the gyro-Z bias for ~2 s (**keep the node still**), then integrates GYRO_ZOUT (0x47,
  ±250 dps) at ~100 Hz in `loop()` with a 0.4 °/s deadband.
- It appends `Yaw:<deg>` before `Seq:`. Temp/Hum/LDR/Accel/Seq, 440 MHz LoRa SF7, and the 250 ms rate are unchanged.
- The yaw is **relative** (0° = power-up heading; there's no magnetometer) and drifts slowly.
- The ESP32 ground station (teensy-lora-video `ESP32_GroundStation`) forwards it as `"yaw"`, and the KCC dashboard
  shows it. The extra ~9 bytes lengthen the LoRa packet slightly, and the 6U/camera slots still fit in the gap.
